# План реализации после 0.1.1

Каждая из 29 задач имеет собственную карточку с точками входа в код, границами изменения, ходом работы и проверкой результата. Первые 26 карточек охватывают реализацию, исследования и проверку существующего управления. Последние три описывают регрессии сохранений. Все карточки открыты. [Пожелания](roadmap.md) · [Архитектура](architecture.md)

## Как выдать одну задачу

Передайте агенту ссылку на карточку с ID и ревизию, включающую её зависимости. Для независимого старта доступны [E01](tasks/E01.md), [V01](tasks/V01.md), [V02](tasks/V02.md), [P01](tasks/P01.md), [R01](tasks/R01.md), [B01](tasks/B01.md), [S01](tasks/S01.md). Для первой проверки существующего поведения подходит E01; для ограниченного изменения с числовым примером — V01. P01 и S02 требуют эксперимента с Build Gun. Успешная компиляция не отвечает на вопросы о поведении в игре.

Исполнитель сдаёт изменение либо протокол исследования и указывает, какие пункты приёмки он действительно выполнил. Проверяющий получает карточку и ревизию, повторяет раздел «Независимая проверка» и отмечает каждый результат. Если доступа к игре нет, укажите, какой сценарий остался открытым. Для исследовательской задачи воспроизводимое ограничение — допустимый результат. У P02 есть дополнительное условие допуска из P01.

## Условия игрового прогона

Используйте отдельный слот одиночной игры. Для сравнений пригодятся асимметричный чертёж с крышей, фундаментом и станком и два экземпляра с разными положениями и поворотами. Для удаления и переименования подготовьте одноразовую копию библиотеки. Запишите ID задачи, ревизию, версии игры и мода, условия, действие и результат. Для геометрии приведите координаты или сопоставимые кадры. Для строительства и удаления сверьте GUID, количество планов, реальных зданий и остатки материалов по условиям карточки. Игровые сохранения хранятся локально. [Сборка и установка](../README.md) · [Протокол игровых испытаний](test-plan.md) · [Проверка сохранений](save-compatibility.md)

При параллельной разработке учитывайте, что ввод и операции сосредоточены в `ShadowPlan.cpp`, формат данных в `ShadowPlan.h`, представления в `ShadowProjection.cpp`. Проверку взаимодействующих функций повторяйте на объединённой ревизии.
