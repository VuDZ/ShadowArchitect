# Производительность больших планировок

Игрок загружает мир с десятками одинаковых модулей, смотрит на них и переключает Ghost, Wireframe и Footprint. Сколько длится пауза при загрузке и переключении? Сколько памяти нужно в этот момент? Как часто игра успевает отрисовать кадр после переключения?

| Задача | Результат |
|---|---|
| [F01. Измерить восстановление и смену вида](01-measure-projection-cost.md) | Повторяемый способ снять время операций, число компонентов, пик памяти и стоимость отрисовки. |
| [F02. Проверить планировки от 10 до 100 модулей](02-benchmark-large-layouts.md) | Таблица замеров относительно пустой сцены и решение по фактическому узкому месту. Выполняется после F01. |
| [F03. Сократить паузу Ghost → Wireframe](03-reuse-components-for-wireframe.md) | Сравнить смену материалов на существующих компонентах с полной пересборкой вида. |
| [F04. Проверить плавность наведения литейных](04-profile-foundry-placement.md) | Узнать, как меняется время кадра с Build Gun у свободной площадки и при пересечении нескольких планов. |
| [F05. Завершить контрольные замеры](05-complete-benchmark-controls.md) | Измерить разброс, влияние диагностики и загрузку GPU и потока отрисовки. Результаты дополняют F01/F02. |

После пилота на 100 модулях начните с контрольной серии F05 на исходной реализации. Её результаты станут точкой сравнения для F03. F04 можно выполнять независимо. Решение об использовании ISM/HISM для устойчивой сцены принимается по результатам F05.

В игровом прогоне V03 два плана дали 38 и 22 компонента в Ghost и Wireframe, по одному в Footprint. Это исходный пример для проверки счётчиков. [Результаты V03](../archive/v-display-modes/03-switch-display-mode.md) · [Условия игрового прогона](../../work-plan.md)
