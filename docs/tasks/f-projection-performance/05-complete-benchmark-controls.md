# F05. Завершить контрольные замеры F01 и F02

**Цель.** Установить, при каком числе видимых модулей появляется заметная задержка, и отделить влияние диагностики от стоимости переключения и постоянной отрисовки. Используйте слоты, генератор и CSV из исходного [пилота F02](02-benchmark-large-layouts.md). Результаты этой серии закроют соответствующие пункты [F01](01-measure-projection-cost.md) и F02 без второго прогона тех же сценариев.

## Независимая проверка

- [ ] Снимите матрицу 0, 10, 25, 50 и 100 экземпляров одного Blueprint на исходной реализации. Сохраните кадр, подтверждающий видимость всей сетки 10×10. Используйте ту же камеру для остальных размеров. Если камеру пришлось сдвинуть, переснимите пустой контроль. Для каждого размера выполните не менее трёх новых процессов с повторной загрузкой слота и полными циклами видов. Разделите первый и прогретый циклы. Используйте равные окна устойчивого состояния, для сравнения с пилотом укажите длительность.
- [ ] На 2 и 100 планах сделайте парные повторы с `-ShadowProjectionProfile` и без него. Сохраните общий кадровый сборщик в обоих случаях. Привяжите кадр выполнения операции к номеру кадра или метке обработанного действия. Отдельно сравните этот кадр и максимум следующих пяти. В контроле без профилировщика используйте независимую метку ввода и явно укажите точность привязки. Так можно проверить, повторяется ли задержка, увиденная на двух планах через два кадра после вызова.
- [ ] Приведите по режимам время кадра p50/p95, FPS, draw calls, число компонентов, а для восстановления и переходов — время операции и изменение памяти процесса по методике F01. Для устойчивых Ghost и Footprint хотя бы на 0 и 100 планах приложите раздельные замеры времени GPU и потока отрисовки с указанием инструмента. Если Shipping не выдаёт эти счётчики, зафиксируйте ограничение и снимите их доступным инструментом на сопоставимой сборке, пометив результаты отдельно. Одни draw calls не позволяют определить узкое место.
- [ ] Для худшего перехода сохраните покадровый участок до, во время и после вызова с отметками фаз. Укажите разброс между процессами и подтвердите сохранность GUID, поз и числа компонентов после циклов. Перенесите результаты в карточки F01/F02, отмечая только фактически проверенные критерии. [Запуск SaveCheck и формат данных](../../background-testing.md#f01-и-f02-время-и-память-проекций)

В выводе дайте два отдельных решения. Для паузы Ghost → Wireframe передайте контрольные цифры в [F03](03-reuse-components-for-wireframe.md). Для постоянно видимых планов укажите, оправдывают ли замеры эксперимент с объединением одинаковых мешей через ISM/HISM. Если измерения не разделяют стоимость GPU и потока отрисовки, сохраните этот вопрос открытым.
