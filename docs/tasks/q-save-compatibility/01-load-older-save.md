# Q01. Проверить чтение схемы предшествующего релиза

**Когда выполнять** — При первом изменении формата сохранения и перед выпуском с таким изменением.

## Цель

Загрузить файл, записанный предшествующей выпущенной версией. Сверить GUID, состав, положения, видимость и значения новых полей. Пересохранить и повторно открыть. Сравнить с [проверенным переходом 0.1.0 → 0.1.1](../../save-compatibility.md).

## С чего начать

Понадобятся две настоящие версии мода и отдельные процессы клиента. Базовый исторический опыт 0.1.0 → 0.1.1 проверял две версии с одной схемой данных. Он не доказывает чтение будущей схемы. [Исходник SaveCheck](../../../tests/compatibility/SaveCheck/Source/SaveCheck/Private/SaveCheck.cpp) · [Протокол совместимости и запуск SaveCheck](../../save-compatibility.md) · [Данные снимка](../../../src/ShadowArchitect/Source/ShadowArchitect/Private/ShadowPlan.h)

## Работа

1. В предыдущем релизе запишите отдельный слот с двумя различимыми планами. Снимите GUID, позы, видимость и состав. Проверьте версию писавшего мода по заголовку слота.
2. Откройте копию кандидатом. Сверьте прежние поля по смыслу и новые — с ожидаемыми значениями миграции. Запишите в новый слот, полностью завершите клиент и откройте результат кандидатом ещё раз.

## Независимая проверка

- [ ] На обоих чтениях присутствуют те же два GUID, позы и визуальные детали; нет дубликатов. Для новых полей, например неизвестной стоимости, проверьте состояние явно.
- [ ] В каждом процессе подтвердите фактическую версию и одну подсистему. `SaveCheck` даёт число акторов и digest записи; при изменении схемы digest может закономерно измениться. Зафиксируйте значения проверяемых полей отдельно.

## Что передать проверяющему

Приложите версии писателя и читателя, исходные и итоговые значения и идентификаторы двух тестовых слотов. Отсутствие старого слота или клиента оставляет эту проверку открытой.
