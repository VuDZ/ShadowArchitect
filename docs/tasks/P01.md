# P01. Проверить перехват подтверждения строительства

**Зависимости** — можно начинать с 0.1.1.

## Цель

Найти точку обработки штатного подтверждения до расхода ресурсов. Результат — техническое решение или предел реализуемости.

## С чего начать

0.1.1 читает голограмму после выбора игрока и строит проекцию отдельным F7. Для режима планирования нужно остановить штатное подтверждение до появления реальной постройки и списания ресурсов. [Управление планами](../../src/ShadowArchitect/Source/ShadowArchitect/Private/ShadowPlan.cpp) · [Захват геометрии](../../src/ShadowArchitect/Source/ShadowArchitect/Private/ShadowCapture.cpp) · [Архитектура](../architecture.md)

## Работа

1. В SDK целевой версии проследите обработку нажатия и отпускания в состоянии Build Gun и шаги голограммы. Зафиксируйте реальные классы, методы и сторону исполнения.
2. В отдельном прототипе включайте перехват только для тестового игрока. Запишите события ввода, номер шага, попытку строительства, изменение ресурсов и появление реального объекта.
3. Повторите сначала без перехвата, затем с ним для фундамента, Blueprint и ленты. Проверьте отмену после первой точки ленты.

## Независимая проверка

- [ ] Для каждой цели предъявите пару трасс одного полного клика. Укажите событие, на котором принято окончательное решение. При остановке финального шага дельты ресурсов и реальных объектов равны нулю.
- [ ] Если штатное подтверждение всё равно проходит или момент зависит от типа объекта, опишите минимальный воспроизводимый случай и границы доступной поддержки. Укажите, может ли P02 безопасно блокировать остальные типы.

## Что передать проверяющему

Сдайте техническое решение с таблицей трёх типов и выводом о допуске P02. Отсутствие опыта в Shipping означает «не проверено»; отрицательный вывод требует наблюдаемого отказа.
