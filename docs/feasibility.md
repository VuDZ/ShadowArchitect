# Техническая реализуемость

**Вывод на 23.11.2026.** Объектные трансформации доступны в реальных файлах Blueprint. SDK целевой сборки также открывает соответствие между зданием во временном мире и его визуальным корнем в активном preview. Это позволяет написать захват без перехвата строительства. Главный открытый вопрос для запуска — остаётся ли полное соответствие доступным в момент нажатия Place Shadow для разных классов зданий. Наличие декларации и экспорта само по себе этого не доказывает. [FGBlueprintHologram.h][holo]

## От файла до визуального корня

1. **Файл.** `FBlueprintHeader` описывает версию сохранения, CL, размеры дизайнера, стоимость и использованные рецепты. Список рецептов не содержит координат отдельных экземпляров. `FBlueprintSaveData` отделяет заголовок, TOCData и BlobData. `UFGBlueprintDescriptor::GetBlueprintNameAsString()` даёт имя для индикации. [FGFactoryBlueprintTypes.h][types]
2. **Временный мир.** Заголовки объявляют `AFGBlueprintSubsystem::CreateBlueprintWorld()`, `GetBlueprintWorldBuildables()`, `LoadStoredBlueprint(..., bool useBlueprintWorld = false, ...)`. Последний API может создавать акторы и требует выбора мира. Повторная загрузка ради проекции вмешалась бы в жизненный цикл общего временного мира. Мод читает уже подготовленный preview. [FGBlueprintSubsystem.h][library]
3. **Объекты.** Публичный `AFGBlueprintHologram::mBuildableToNewRoot` отображает `AFGBuildable*` временного мира в `USceneComponent*` визуализации. Заголовок также объявляет `DuplicateMeshComponentsFromBuildableArray`, `AlignBuildableRootWithBounds`, отдельную карту сплайнов и регистрацию пользовательских визуализаторов. По ключу берётся класс, по значению — точный transform корня относительно голограммы. Это учитывает смещение pivot после выравнивания. Если вместе с текущим дескриптором ещё доступен список временных зданий, захват проверяет, что каждому живому зданию соответствует визуальный корень. [FGBlueprintHologram.h][holo]
4. **Положение.** Путь от локальной пешки — `AFGCharacterPlayer::GetBuildGun()`, `AFGBuildGun::GetCurrentState()`, `UFGBuildGunStateBuild::GetHologram()`, затем `AActor::GetActorTransform()`. Мод читает уже полученный результат вращения, привязки и Nudge. `AFGBuildableHologram` и его производные продолжают обрабатывать штатное позиционирование. Переопределять `Construct`, заменять ЛКМ или удерживать временную голограмму не требуется. [Персонаж][player] · [Build Gun][gun] · [Состояние строительства][state] · [Механика голограмм][hologuide] · [Механика Native Hooks][hooks]
5. **Визуализация.** Из визуального поддерева сохраняются ссылки на статические mesh assets, относительные трансформации и габариты конкретного здания. ISM раскрывается по экземплярам. Для деформированных сплайнов, анимированных компонентов и недоступных assets используется отдельный ориентированный proxy по измеренным габаритам. При отсутствии визуальных мешей допускаются локальные габариты компонентов исходного здания. Такой proxy может включить служебные компоненты. Для объектов без измеримых размеров захват возвращает ошибку. Материал взят из игрового контента. Наличие пути в Starter Project проверено, внешний вид в Shipping ещё не проверялся. [Материалы Build Gun](https://github.com/satisfactorymodding/SatisfactoryModLoader/tree/v3.12.1/Content/FactoryGame/Equipment/BuildGun/Material)
6. **Сохранение.** Нативный класс Game World Module с `bRootModule` обнаруживается через `FPluginModuleLoader::FindRootModulesOfType`. На фазе CONSTRUCTION `UGameWorldModule` регистрирует `ModSubsystems`. Менеджер ищет существующий актор по стабильному имени до создания нового. Собственный `AModSubsystem` явно реализует `IFGSaveInterface`, возвращает true из `ShouldSave_Implementation()` и хранит поля SaveGame. Визуализация восстанавливается из этих полей при BeginPlay или после загрузки в уже запущенном мире. [Поиск модулей][loader] · [Регистрация][module] · [Поиск сохранённой подсистемы][manager] · [Контракт сохранения][save] · [Руководство SML][subguide]

## Что проверено экспериментом

- **Данные на диске.** Python-проба прочитала таблицы объектов 25 локальных файлов формата Blueprint v2 / save 60, включая три многоблочных файла. Получено 590 записей акторов 32 классов. В одном смешанном Blueprint найдены 3 конструктора, 6 лент, 4 провода, 2 столба, разделитель и объединитель. Свойства сетей и содержимое инвентарей для этого опыта не извлекались. [Код пробы](../scripts/probe_blueprint.py)
- **Независимое представление.** Из копии файла размером 1047 байт с SHA-256 `14231CCBDF66A71C0378AB6E6BB1F1DE1DDEDA7BFCC73374931B770AC5C580BA` записана модель OBJ. В исходнике 16 разных центров на сетке 4×4. По X и Y встречаются −1200, −400, 400, 1200 см, Z равен 50 см. В OBJ каждому актору соответствует отдельный параллелепипед 800×800×100 см. Координаты, масштаб и кватернион прочитаны из таблицы. Размер примитива задан для конкретного класса фундамента. Модель можно открыть без игры и оригинала Blueprint. [Результат](foundation-spike.obj)
- **Двоичный API.** Через `dumpbin /exports` на установленных Steam Shipping DLL подтверждены, среди прочих, `UFGBuildGunStateBuild::GetHologram`, `AFGHologram::IsDisabled`, `AFGChatManager::AddChatMessageToReceived`, `AActor::CalculateComponentsBoundingBoxInLocalSpace(bool,bool)`, `UInstancedStaticMeshComponent::GetInstanceTransform`, `AModSubsystem::BeginPlay` и `USubsystemActorManager::RegisterSubsystemActor`. Поля карты проверены по заголовку тега. Эксперимент с OBJ не вызывает этот C++ код.

## Ghost Construction и границы подхода

В каталоге Ghost Construction указаны версия 1.0.9 и зависимость SML ^3.12.0. В открытом репозитории есть отдельные `Build_GhostConstructor`, `Build_GhostAssembler`, рецепты, дескрипторы и `Material_Ghost` в виде .uasset. Это свидетельствует о подготовленных макетах конкретных зданий. По опубликованному дереву нельзя подтвердить универсальный захват пользовательского Blueprint или точную реализацию текущего релиза. Shadow Architect не требует каталога вручную созданных копий станков. [Страница мода](https://ficsit.app/mod/GhostConstruction) · [Репозиторий](https://github.com/DellAquila/GhostConstruction)

**После обновления игры** сначала сверить CL, SML и декларации карты, пересобрать DLL, затем повторить A и D. Даже при сохранении сигнатур могут измениться время заполнения карты, иерархия визуальных компонентов, имена материалов и обработка ввода другими модами. Для модифицированных машин особое значение имеет пользовательский визуализатор. Если карта окажется недоступной, первый диагностический шаг — сравнить временные здания и визуальные корни на зафиксированном preview. Альтернатива для отдельной итерации — проверенный доступ к таблице акторов файла с отдельным разрешением геометрии классов и привязкой pivot. Офлайн-проба не декодирует свойства сплайнов и не подменяет игровой загрузчик.
